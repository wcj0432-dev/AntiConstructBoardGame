# v0.5 语义文本与原创矢量素材

本版使用项目内原创 SVG。资源随 Vite、离线单文件和桌面版一并打包，不依赖在线图片、字体或素材服务。没有使用《钢铁雄心4》或其他游戏的角色、地图、贴图、标志和界面素材。

## 统一决策语义

入口为 `src/ui/SemanticText.tsx`，样式为 `src/ui/v5-ui.css`。应用在现有 `command.css` 之后导入新样式，以保留统一的正文、标签字号和 UI 缩放。

语义 token 使用数据结构，组件不接受原始 HTML，也不解析字符串中的任意标签。

| token 的 `type` | 用途                               | 非颜色提示                                 |
| --------------- | ---------------------------------- | ------------------------------------------ |
| `text`          | 保持大部分叙述为普通文字           | 无额外装饰                                 |
| `entity`        | 人物、机构、地区、事务、项目引用   | 对象图标、下划线；传入导航回调后成为按钮   |
| `cost`          | 行政命令、财政、政治资本、物资消耗 | 资源图标、明确数字；可用量不足时标注“不足” |
| `capability`    | 行动能力与资格                     | 特殊能力图标；可标注“已具备／未满足”       |
| `permission`    | 行动组织权限                       | 权限图标；可标注“已具备／未满足”           |
| `condition`     | 当下已满足或未满足的条件           | 勾选／叉号、“已满足／未满足”文字           |
| `effect`        | 确认后的结果、代价、能力解锁       | 代价警告图标；解锁显示图标及“解锁”文字     |
| `deadline`      | 授权期限、工程期限及紧急后果       | 时钟图标、明确期限文字                     |

条件状态应从当前游戏状态和同一次行动预览计算。语义组件没有独立的游戏状态缓存；不要把旧预览的 `met` 值长期保存在 UI 中。组件也不自行执行命令和扣费。

```tsx
import {
  SemanticText,
  ConditionsList,
  CostSummary,
  RelatedNetwork,
} from "./ui/SemanticText";

<SemanticText
  tokens={[
    "需要",
    { type: "capability", text: "高级异常封印", met: hasSeal },
    "与",
    { type: "entity", entity: {
      kind: "office", id: "gov-north", label: "北境省政府",
    } },
    "的授权，完成后",
    { type: "effect", text: "解除异常源", tone: "benefit" },
    "。",
  ]}
  onEntityClick={navigateToEntity}
/>

<ConditionsList conditions={[
  { label: "地方武装指挥权", met: preview.hasCommand,
    reason: preview.commandReason,
    remedy: ["在政策改革中调整事务主责或提出具体授权。"] },
]} />

<CostSummary costs={[
  { resource: "treasury", amount: preview.treasury,
    available: game.core.treasury },
]} />
```

`ConditionsList` 的 `reason` 常驻显示，未满足条件的 `remedy` 提供解决方式。`CostSummary` 逐项显示消耗和可用量。`RelatedNetwork` 采用显式节点与关系边，显示受阻原因和待生效状态；它不会推测制度关系或凭装饰线条制造不存在的权限。

财政与项目表格可以使用 `.v5-table-region` 包装。该区域有局部滚动、固定表头、键盘焦点样式，正文使用 `--body`（默认 16px），次要标签使用 `--label`（默认 14px）。交互元素的状态同时依赖文字和图标，支持 `prefers-contrast: more`。

人物名称、职业和实际能力仍由游戏数据与旁边的正文显示。SVG 只表达视觉身份，不能用徽记代替规则说明。未知人物 ID 使用同一风格的稳定备用模板。每个 SVG 的裁切 ID 使用 React `useId`，同一人物可以同时出现在名册、事件和提示中。

这是一套统一、可维护的原创模板，不是已完成的 24 张高质量手绘立绘。后续可按相同尺寸和构图逐人替换为更精细的原创插画。

## 地图和建设反馈

`V5_REGION_PATHS` 提供六个地区的 SVG 路径，索引与现有地图地区一致，保留原坐标和点击目标。轮廓增加海岸和边界起伏，不扩大地图面积。

`MapGeographyV5` 返回 SVG `<g>`，放在省份底色上方、地区名称和实时危机标记下方：

- 中央工业省：河道、首都天际线、工业厂区和调度路径。
- 南岭修仙省：山地、宗门建筑、灵脉与矿点。
- 北境异常省：山脉、林地、边防塔和异常裂隙。

静态地标表达世界观地理，不自动增加收入、库存、机构或工程。地貌层设置 `pointerEvents="none"`，不会截断地图点击、缩放、拖动和提示。

`FacilityMarkerV5` 从实际工程的状态绘制不同标记：

| 工程状态       | 显示                       |
| -------------- | -------------------------- |
| `construction` | 金色虚线外圈与工程类型图标 |
| `completed`    | 浅绿实线外圈与正式设施图标 |
| `paused`       | 红色外圈和暂停符号         |

能源、铁路、预警、农场、合作社、港口、工业设施及能力传承学院采用不同图标。该组件只展示调用方传入的真实状态，不创建工程、连接或产出。

上述素材已接入 `Visuals.tsx` 和 `GameMap.tsx`。地貌按地区路径裁切，裁切 ID 对每个地图实例唯一。设施提示与地区提示使用并列的 SVG 图层，避免悬停一个设施时同时出现两个重叠提示。取消工程不会留下建设标记。

全国灵能电网显示南岭与工业省之间的真实供给线，运转、停运、故障和施工采用不同线条。状态读取 `gridOperating` 与工程网络数据，经营权、受益地区及出资份额读取同一份 `workFunding` 合同；图形不会自行推算另一套经营规则。原有实际铁路连接继续保留。

```tsx
import { MapGeographyV5, FacilityMarkerV5 } from "./ui/art/V5Art";
<svg viewBox="0 0 1000 650">
  {/* 省界 */}
  <MapGeographyV5 />
  {/* 名称与实时事务标记 */}
  <FacilityMarkerV5 type="energy" status="construction" x={250} y={460} />
</svg>;
```

## 事件档案构图

`EventArtV5({kind,title})` 按现有事务种类提供统一宽幅构图：工业档案与巡检清单、异常巨眼与损坏厂区、物资列车与仓库、群众诉求与文书、灵脉开发、报纸、国家目标仪式。普通行政事务保持公文式表达，重大异常使用更明显的奇幻主题。

它们是主题示意插画；画中的人物、工厂和列车不表示额外单位或真实工程。新事件种类可以继续复用这个接口，后续再增加独立构图。

## 当前边界

本版没有新增摄影、生成图片或第三方贴图库；素材制作方式为项目源码中的原创 SVG。未完成大型地图扩张、独立地形纹理系统、逐人手绘立绘和每个事件各一张大型插画。所有文件可以在源码包中编辑，并随离线发布包使用。
